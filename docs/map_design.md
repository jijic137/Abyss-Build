# 深渊猎手 · 地图构造设计文档

> 版本：v2（2026-08） · 状态：实施中
> 目标：以正方形房间为基元，构造出多样、可读、耐探索的搜打撤地图，
> 并保持与现有玩法逻辑（探索/撤离/锁门/宝箱/战役小关）完全兼容。

---

## 1. 设计理念

地图是「搜打撤」循环的舞台。一张好地图应该同时做到：

1. **可读**：玩家能通过房间大小、结构、装饰快速判断"这是什么地方、有没有危险"。
2. **可探索**：房间之间有选择性（绕路、取舍），而不是一条走廊直通撤离点。
3. **有记忆点**：每局生成的大房间、特殊结构、错位通道让玩家记住"这张图长什么样"。
4. **公平**：随机生成永不产生死局（出生房可出、撤离房可达、钥匙可获取）。

实现上采用「**网格基元 + 分层叠加**」：
所有玩法逻辑仍以"网格单元 = 逻辑房间"为抽象（房间索引、门、BFS、锁门、
事件、容器归属都不变），视觉与空间结构则在其上叠加多样层。

---

## 2. 基元

### 2.1 网格单元

- 单元内边 `ROOM = 700px`，墙厚 `WALL = 36px`，节距 `SEG = 736px`。
- 档位网格：T1 `4×3`、T2 `4×4`、T3 `5×4`、T4 `5×5`、T5 `6×5`。
- 每个单元是一个**逻辑房间** `rooms[idx]`，携带 `type / c / r / idx`。
- 房间邻接门：水平 `doorsH[c][r]`、垂直 `doorsV[c][r]`。

### 2.2 连通骨架

- Randomized Prim 生成最小生成树（保证全图连通）；
- 按**拓扑风格**追加回边（环），控制"迷宫感 vs 开放感"。

---

## 3. 五层多样性

### 层 1 · 拓扑风格（全局节奏）

每局由种子决定整体风格，影响回边密度与房间合并概率：

| 风格 | 回边概率 | 合并概率 | 观感 |
|------|---------|---------|------|
| `maze`     | 0.10 | 0.18 | 走廊密、死胡同多、压迫感强 |
| `standard` | 0.22 | 0.30 | 均衡（默认） |
| `open`     | 0.34 | 0.42 | 环多、大厅多、节奏快 |

风格由 `rng` 加权选择（standard 权重最高）。

### 层 2 · 房间合并（大空间）

**规则**：
- 只合并"类型仍为战斗房"的格子，特殊房（出生/撤离/宝库/精英/BOSS/圣泉/祭坛）保持单格；
- 支持 1×2、2×1、2×2 以及 L 形（2×2 缺一角）；
- 合并组内部的所有邻边门强制开启并标记 `internal`（渲染时不画墙段，视觉合一）；
- 组内格子共享类型：任一成员被改为精英/陷阱/道具房时，整组同步；
- 内部墙不参与锁门。

**收益**：大战斗房提供走位空间、多入口包围战、Boss 战舞台感；
L 形房提供墙角卡视野、绕背的战术空间。

### 层 3 · 房内结构（单格战斗房）

约 45% 的单格战斗房生成内部结构，由种子确定，渲染为实心墙块：

| 结构 | 形状 | 战术特征 |
|------|------|---------|
| `pillar` | 中央 90×90 柱 | 绕柱风筝、卡弹道 |
| `cross`  | 中央十字矮墙 | 四角分割，聚怪/隔断 |
| `corner` | 左上 L 角墙 | 掩体、伏击点 |
| `alcove` | 上下两侧隔间墙 | 门口压制、侧翼包抄 |
| `ruins`  | 3~5 块随机碎石 | 无规律掩体，近战友好 |

**安全约束**：
- 房间中心 160px 区域永远留空（出生/撤离/容器锚点不被阻挡）；
- 门口带（门宽 104px 的延伸区）永远留空；
- 容器生成时与结构矩形做重叠检测，重叠则重新取点。

### 层 4 · 错位门

每扇门沿墙方向随机偏移（±140px，保证门边距墙端 ≥150px）：

- 相邻房间的通道不再对齐，玩家经过门洞时视野发生"错位"；
- 结合房内结构，形成进门即需要判断左右掩体的节奏；
- 门偏移写入 `map.doorOffs`，渲染、碰撞、锁门、小地图统一读取
  `G.Map.doorRect / doorCenter`。

### 层 5 · 主题内容分布

保持既有内容系统（由 52_chests / 55_campaign / 14_map 负责）：

- 撤离房 = 最远格（BFS 最大距离）；
- 精英 / 宝库 / 圣泉 / 祭坛 / BOSS 房 = 按距离权重远离出生点；
- 陷阱房 / 道具房 = 战斗房转换（52_chests），转换时整组合并房同步；
- 小关战役（55_campaign）把深度附加的宝箱/陷阱布置进战斗房。

---

## 4. 随机与确定性

- 地图完全由 `seedFromTier(tierId, salt)` 决定，支持存档读档重建；
- 所有随机走 `Rng(seed)`（mulberry32 变体），不依赖全局 `Math.random`；
- 新多样性层（风格/合并/结构/门偏移）均从同一 `rng` 序列取数，
  保证同一种子永远生成同一张图。

---

## 5. 硬性保证（可验证）

1. **全连通**：Prim 生成树保证任意两房可达；
2. **出生自由**：出生房所有相邻门永不锁（0 钥匙也能出房）；
3. **撤离可达**：锁门视为墙后，出生房 → 撤离房仍无需钥匙可达；
4. **钥匙可获**：锁门后出生侧保留至少一个钥匙来源房（宝库/精英/BOSS）；
5. **结构不堵路**：房内结构与门带/中心区互斥；
6. **接口兼容**：`cols/rows/rooms/doorsH/doorsV/roomRect/roomAt/solid/…`
   语义不变，探索、撤离、锁门、战役、小地图全部沿用。

以上 1-4 由冒烟档案 R 逐张地图验证（300 张随机图）。

## 6. 数据模型增量

```js
map = {
  // ……既有字段不变
  doorOffs: { 'H:c:r': ±px, 'V:c:r': ±px },   // 门沿墙偏移
  internalDoors: { 'H:c:r': true },             // 合并房内部通道
  interior: [ { room, kind, rects: [[x0,y0,x1,y1], …] } ],
  interiorByRoom: { idx: [rects…] }              // solid 快速查询
}
rooms[i].group = leaderIdx   // 合并组成员指向主格（未合并 = 自己）
```

## 7. 未来扩展（预留）

- **主题地图模板**：区域级"概念图"（裂隙走廊 / 矿坑竖井 / 深渊圣殿），
  用同一生成器 + 区域装饰表（29_env 的 biome 系统）替换贴图与结构权重；
- **隐藏房间**：仅通过事件/钥匙/爆炸进入的密道（在合并层之上加"暗门"边）；
- **垂直维度**：2 层楼板 + 楼梯单元（需要渲染分层，改动较大，暂缓）；
- **动态地形**：战斗后塌陷/开门，改变后续路径（事件驱动）。
